Información de privacidad

Pendiente de revisión humana y legal. Revisa y adapta esta información para la jurisdicción, la instalación y el piloto concretos antes de publicar la aplicación o invitar participantes. No se han inventado datos de contacto.

CódigoClaro gestiona los datos. Esta página describe la información que puede tratar la aplicación y las transferencias realizadas por funciones opcionales.

1. Datos de cuenta y aprendizaje

Al crear una cuenta se almacenan el nombre visible, el correo electrónico, un hash de la contraseña, la fecha de alta y el último acceso. Para mantener el progreso se pueden guardar temas completados, resultados de tests, tareas y sesiones de estudio, fragmentos guardados voluntariamente y comentarios enviados mediante Feedback.

2. Finalidad y almacenamiento

Estos datos se usan para iniciar sesión, conservar el progreso, corregir tests y gestionar el contenido enviado por Feedback. El borrador local del IDE se guarda en el almacenamiento del navegador y no se sincroniza por sí solo con la cuenta. La base de datos está en el servidor de la instalación.

3. Cuenta, sesión y eliminación

La aplicación usa una cookie HttpOnly y SameSite=Lax para mantener la sesión. La eliminación de una cuenta borra sus datos de la base de datos activa; el proveedor de alojamiento podría conservar copias de seguridad según su servicio. Esta versión no verifica el correo ni permite restablecer la contraseña.

4. Bibliotecas y servicios externos

Algunas funciones del IDE cargan bibliotecas desde redes de distribución de contenido (CDN). Si pulsas “Comprobar conexión”, el navegador consulta el endpoint de Java para leer los lenguajes disponibles. La petición puede incluir el token opcional si lo has introducido, pero no incluye tu código ni el texto de entrada (stdin).

Para ejecutar Java, Kotlin, Node.js, Python o TypeScript en remoto, solo después de marcar el consentimiento de la sesión y pulsar “Ejecutar”, se envían el código fuente y el contenido de stdin al endpoint HTTPS mostrado en el IDE (por defecto, https://ce.judge0.com). Si has escrito un token, también se envía en la petición de ejecución. El servicio remoto puede aplicar sus propias condiciones y límites; no envíes código con datos personales o secretos. El token permanece en el campo durante la sesión y no se guarda. El borrador local del IDE no se envía automáticamente. La ejecución local de JavaScript usa un worker sin acceso a red; la vista previa de HTML/CSS elimina scripts, navegación y recursos externos. React/JSX genera HTML estático en un worker local; el código no se transmite, y la vista previa no ejecuta eventos, efectos ni scripts.

Kotlin y PL/SQL ofrecen análisis estático; Node.js, MongoDB, Firestore y backend tienen funciones simuladas.

5. Seguridad y límites

La aplicación usa hash de contraseñas, consultas parametrizadas y sesiones protegidas. Estas medidas no equivalen a una auditoría independiente. No introduzcas contraseñas, tokens, claves API ni información personal en el código del IDE.
