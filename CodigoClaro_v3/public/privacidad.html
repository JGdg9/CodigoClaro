Información de privacidad

Documento de piloto que requiere completar antes de una publicación pública. El responsable del proyecto debe añadir su identidad y una dirección real de contacto, revisar la base jurídica, los plazos de conservación y los requisitos aplicables. Este texto no sustituye el asesoramiento legal.

1. Responsable

Proyecto: CódigoClaro. Responsable: [sustituir por nombre o entidad responsable]. Contacto de privacidad: [añadir correo de contacto]. No publiques esta política dejando los campos pendientes.

2. Datos tratados

Para el piloto se almacenan el nombre visible, correo electrónico, hash de la contraseña (nunca la contraseña en texto plano), fecha de alta y último acceso; XP, temas completados, resultados de tests, tareas del plan de estudio, fragmentos de código guardados voluntariamente y comentarios enviados al equipo. Se registra actividad básica de uso (por ejemplo, envío de test o feedback).

3. Finalidad y acceso

Se utilizan los datos para iniciar sesión, conservar el progreso entre sesiones, corregir tests, dar soporte y evaluar la utilidad de la versión piloto. Los administradores autorizados pueden ver la información necesaria para gestionar la prueba, incluidas cuentas y comentarios. No se ha integrado publicidad ni analítica comercial de terceros. El IDE guarda un borrador local del código en el navegador; ese borrador no se sincroniza por sí solo con la cuenta.

4. Base jurídica, conservación y derechos

Antes de recoger datos de participantes reales, el responsable debe documentar una base jurídica válida, concretar cuánto tiempo conservará los datos, definir un proceso de atención de derechos y añadir el contacto correspondiente. En este piloto, la eliminación de la cuenta borra los datos vinculados almacenados en la base de datos activa; pueden quedar copias de seguridad del propio anfitrión si las crea. No hay verificación de correo ni recuperación automática de contraseña.

5. Cookies y almacenamiento

El servidor utiliza una cookie de sesión HttpOnly y SameSite=Lax para mantener el acceso. No se ha añadido una plataforma de cookies publicitarias. La sesión es necesaria para autenticar las solicitudes y no se usa para publicidad.

6. Proveedores y transferencias

La base de datos está en el servidor en el que se despliegue CódigoClaro. Algunas funciones educativas cargan bibliotecas desde redes de distribución de contenido (CDN). Si pulsas “Comprobar conexión” en el IDE, el navegador consulta el endpoint de Java configurado para leer los lenguajes disponibles; esa petición puede incluir el token opcional si lo has introducido, enviado en la cabecera de autenticación, pero no incluye tu código ni el texto de entrada (stdin). Para compilar Java, solo después de marcar el consentimiento de la sesión y pulsar “Ejecutar”, el navegador envía el código fuente y el contenido de stdin al endpoint HTTPS que aparece en el IDE (por defecto, https://ce.judge0.com). Si has escrito un token, también se envía en la petición de ejecución. El endpoint puede ser operado por un tercero; CódigoClaro no controla su tratamiento ni su retención posteriores. No envíes allí código con datos personales o secretos. El token opcional permanece en el campo durante la sesión y no se guarda. El borrador local del IDE no se envía automáticamente. Kotlin y PL/SQL ofrecen análisis estático; Node.js usa un simulador.

7. Seguridad y prueba

Se aplican hash de contraseñas, sesiones con cookie protegida, consultas parametrizadas, validación básica y límites de solicitudes. Estas medidas no equivalen a una auditoría de seguridad. Para una prueba pública son obligatorios HTTPS, secretos de entorno, copias de seguridad controladas, actualización de dependencias y revisión legal/técnica del alojamiento.
