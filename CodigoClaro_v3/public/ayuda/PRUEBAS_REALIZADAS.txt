INVENTARIO Y CALIDAD DE PDF
- Los 75 temarios principales ocupan tres páginas cada uno y conservan sus 10 secciones en flujo continuo. Las explicaciones se atribuyen a documentación primaria enlazada y el catálogo registra la paginación real.
- Se verificaron los 90 PDF de public/temarios. Los 75 temarios coinciden con el catálogo y las copias en docs/temarios y public/temarios son idénticas byte a byte.
- Las seis rutas complementarias incluyen TypeScript, SQL, NoSQL, Backend/APIs, POO y gestión de bases de datos. Los enlaces públicos resuelven y las URL heredadas de PDF y guías siguen funcionando.
- Revisión visual por muestreo: Java Temas 01 y 12, Python Tema 14, Kotlin Tema 13 y React Tema 11. También se midió la ocupación de las 225 páginas de los 75 PDFs; no se inspeccionaron visualmente uno por uno los 90 PDF de la biblioteca.

CUESTIONARIOS E IDE
- El banco del servidor contiene 320 preguntas: 20 distintas en cada una de 16 tecnologías, con niveles básico, intermedio y avanzado.
- El aula estática combina 88 preguntas iniciales con 375 generadas desde el banco compartido: 463 entradas en total y al menos 20 preguntas únicas en cada uno de sus 19 filtros tecnológicos individuales. TypeScript y PostgreSQL ya tienen filtro propio; Web y Programación son filtros agrupados.
- El IDE ejecuta Java mediante un endpoint HTTPS configurable solo si la persona marca el consentimiento de la sesión. Se transmiten el código y la entrada estándar; el token opcional solo vive en el campo de la página y no se guarda; la ejecución se cancela tras 30 segundos. La comprobación de conexión no envía código, limita la espera a 10 segundos e ignora resultados de intentos anteriores. Kotlin conserva análisis estático.
- Las pruebas del IDE usan un servicio simulado y verifican el bloqueo sin consentimiento, la selección de runtime por endpoint, el timeout y el flujo de salida. No se envió código real a Judge0.

VERIFICACIÓN Y ALCANCE
- npm test: 113 pruebas contabilizadas; 108 pasaron, 0 fallaron y 5 de integración PostgreSQL se omitieron por no existir una base de pruebas configurada.
- El workflow de GitHub Actions crea una PostgreSQL 16 efímera y activa esas cinco integraciones. Falta comprobar el primer resultado de CI con esta rama.
- python verificar_entrega.py: superado; comprueba catálogo, paginación, PDFs, recursos, enlaces y sintaxis. scripts/verificar_pages.py: superado para los 75 temarios y sus PDF.
- La demo de GitHub Pages se sirve desde main. Esta revisión local no confirma el estado del último despliegue remoto; los cambios de esta rama aún no están publicados. No se validó un endpoint de Render ni una base PostgreSQL real.
- En producción, el registro de cuentas nuevas permanece cerrado hasta completar la identidad y el contacto del responsable de privacidad. El cierre no desactiva la ruta de inicio de sesión; el servicio y la base de datos deben estar disponibles.
- Ambos backends limitan los intentos de acceso con contadores en memoria acotados por proceso. CF-Connecting-IP solo se usa cuando TRUST_CF_CONNECTING_IP=true; los blueprints de Render lo habilitan porque Cloudflare sustituye esa cabecera en su proxy. Al alcanzar la capacidad se rechazan nuevas claves hasta que caduquen las activas; los contadores no se comparten entre procesos ni sobreviven a reinicios. PostgreSQL también rechaza el secreto de sesión de ejemplo conocido al arrancar en producción.
- No se conectó a Neon ni a otra base PostgreSQL real. No se validaron los motores externos/CDN de Python, SQL o React en un navegador real.
